RETURN ON AI

問うべきは「AIを導入したか」ではない。「AIが何を生み出したか」だ。

1億円を投資した。100個のAIエージェントを作った。全社員に生成AIを配った。それ自体は成功ではありません。売上・利益・時間・速度・リスク・新しい価値として、AIが何を返したか。それを経営指標として扱うのが Return on AI（ROAI） です。

Return on AI（ROAI）の定義

Return on AI とは、AIへの投資額ではなく、AIが返した経営成果で投資を評価する指標です。株式会社COREが提唱し、診断・設計・開発・運用のすべての工程で一貫して使っています。会計基準の公式指標ではなく、AI投資を経営判断できる形にするための戦略KPIとして扱います。

ROAI ＝ AIが生んだ経済価値 ÷ AI投資総額

分子と分母に何を入れるかを先に決めることが、計測の第一歩です。
分子：AIが生んだ経済価値分母：AI投資総額
売上の増加（Revenue Gain）開発（Development）
コスト削減（Cost Savings）導入（Implementation）
時間の回復・人件費換算（Productivity Value）ライセンス・API利用料
損失の回避（Loss Avoidance）インフラ（Infrastructure）
リスクの低減（Risk Reduction）教育（Training）
新しい価値（Innovation Value）運用・保守（Operation / Maintenance）

AI投資が成果にならない5つの理由

失敗の多くは技術ではなく、始め方と終わり方にあります。COREはこの5つを最初に潰します。

  1. ツール導入で終わる。 ChatGPTやCopilotを配って「導入した」ことにする。業務も組織も変わらないので、成果が数字に出ない。
  2. ベースラインが無い。 導入前の時間・コスト・売上を測っていないので、後から「返った」と言えない。
  3. 技術から始める。 「AIで何ができるか」から始めると、使われない仕組みができる。「どこで価値が失われているか」から始める。
  4. データと手順が整っていない。 Excelと紙と担当者の頭の中に散らばったまま作ると、AIは動かない。先に整えるほうが速い。
  5. 納品がゴールになる。 作って納めて終わり。運用・計測・改善が無いので、初期の効果が薄れていく。

CORE ROAI MODEL — AIが返すものを5つのReturnで測る

すべてのAI案件を、Before → 変革 → After → 計測 → ROAI まで追いかけるための分類です。売上とコスト削減だけでなく、速度・損失回避・新しい価値も経済価値として数えます。

#Return何を増やす／減らすか内容
01GROW売上・利益・顧客価値を増やす営業の時間を商談へ戻し、見込み客への返答を速め、既存顧客からの売上を増やす。
02SAVEコスト・工数を減らす転記・チェック・定型文書・メール対応など、人がやる必要のない仕事をAIと自動化へ移す。
03ACCELERATE企業の速度を上げる意思決定・承認・調査・提案・開発のリードタイムを縮め、機会を逃さない会社にする。
04PROTECT損失・リスクを減らす情報漏洩・人的ミス・不正・属人化・品質事故を、起きる前に検知して減らす。
05CREATE新しい価値を生む自社のデータと業務を、新しいサービス・顧客体験・事業へ変える。

売上に出ない価値も、経済価値として数える（Loss Avoidance）

サイバー攻撃を防ぐ。障害を防ぐ。情報漏洩を防ぐ。契約リスクを見つける。人的ミスを防ぐ。売上として表示されなくても、大きな経済価値があります。

期待損失（Expected Loss）＝ 発生確率（Probability of Event）× 想定損失額（Estimated Impact）

発生確率×想定損失額で「期待損失」を置き、AIで減らせる分を Loss Avoidance として数えます。確定した損害額のようには見せず、必ず幅と前提を添えて出します。CORE ROAI SCORE では対策段階に応じた年間発生確率（点検・監査あり 3%／基本対策のみ 8%／担当者まかせ 15%）と削減率 40% を仮定として明示します。

投資の上限は、価格ではなくリターンから逆算する

年間に見込める経済価値と目標ROAIから、合理的な投資規模を導きます。金額の妥当性は、相見積もりではなくリターンで判断すべきものです。

年間の潜在経済価値 ÷ 目標ROAI ＝ 投資余力の目安（例：年間3,000万円 ÷ 5.0倍 ＝ 600万円）

上記は前提を置いた試算例です。実際の投資規模は、貴社の現状データに基づく CORE ROAI SCORE の診断結果から算出します。

CORE TRANSFORMATION LOOP — Build and Leave ではなく、Build, Measure and Evolve.

納品をゴールにしません。次の8段を回し続けます。

  1. UNDERSTAND 理解する：事業・業務・数字・データ・リスクを読む。どこで価値が失われているかを特定する。
  2. DEFINE 定義する：経営目標・ベースライン・KPI・目標ROAIを決める。ここで「作るもの」はまだ決めない。
  3. REDESIGN 再設計する：人・AI・エージェント・ソフトウェア・データの役割分担で、業務と組織を組み直す。
  4. BUILD 作る：最適な技術を選んで作る。AIが不要なら使わない。自動化で足りるなら自動化にする。
  5. DEPLOY 導入する：現場に入れて、使われる状態にする。教育・運用ルール・セキュリティを含めて配備する。
  6. MEASURE 測る：BeforeとAfterを同じKPIで測る。時間・コスト・売上・リスク・速度の変化を数字にする。
  7. OPTIMIZE 改善する：測った結果から、プロンプト・業務・モデル・コストを改善する。
  8. SCALE 広げる：効いたものを他部門・他拠点・他事業へ広げる。次の投資判断へつなぐ。

Technology follows Strategy. 最適ならOpenAI、Claude、Gemini、オープンソース。AIエージェントが不要なら使わない。自動化で十分ならAIすら使わない。COREは技術を売る会社ではなく、経営成果のために最適な技術を選ぶ会社です。
